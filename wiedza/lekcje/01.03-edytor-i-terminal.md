# Lekcja 1.3 — Edytor i terminal: workflow ucznia

## Cel
Po lekcji uczeń:
- Ma działającą konfigurację: edytor (VS Code) + terminal otwarte obok siebie
- Rozumie strukturę katalogów kursu (`kurs/zadania/`, `kurs/lekcje/`)
- Zna minimum komend terminala: `cd`, `pwd`, `ls`, `python3 plik.py`, Ctrl+C
- Wie, gdzie szukać pomocy (`kurs/JAK-PISAC-KOD.md`)

## Krok 1 — Zakotwiczenie (3 min)
**Pytanie wejściowe:**
> "Gdy coś robisz w kuchni, jak masz ustawione narzędzia? Z którego sięgasz najczęściej?"

**Co chcesz usłyszeć:** narzędzia pod ręką, blisko siebie, każde ma swoje miejsce. To samo dotyczy stanowiska programisty.

## Krok 2 — Mostek (5 min)
**Mostek:** "Programowanie też ma swoje 'stanowisko'. Dwa główne narzędzia: **edytor** (gdzie piszesz kod) i **terminal** (gdzie go uruchamiasz). Trzymamy je obok siebie — tab/alt-tab to za wolno."

Pokaż uczniowi screenshot albo niech sam ułoży:
- Lewa połowa ekranu: edytor (VS Code)
- Prawa połowa: terminal w katalogu projektu

**Pytanie:** "Gdyby Twój edytor zniknął na chwilę, mógłbyś napisać kod? A gdyby zniknął terminal?"

## Krok 3 — Eksperyment (15 min)
Niech uczeń **sam** wykona:

1. Otwórz VS Code → `File → Open Folder` → katalog `ITMOBILE-kurs-python`
2. W VS Code otwórz wbudowany terminal: `View → Terminal` (lub `` Ctrl+` ``)
3. W terminalu wpisz `pwd` — co pokazuje?
4. `ls` — co widać? Czy widzisz katalog `kurs/`?
5. `cd kurs` → `pwd` → `ls`
6. `cd ..` (wraca o jeden katalog wyżej) → `pwd`

**Po każdym kroku pytaj:** "Gdzie teraz jesteś? Co tu widzisz?"

Dalej:
7. Utwórz katalog: `mkdir kurs/zadania/01-test`
8. W VS Code otwórz nowy plik, zapisz jako `kurs/zadania/01-test/hello.py` z treścią `print("ok")`
9. W terminalu uruchom: `python3 kurs/zadania/01-test/hello.py`

## Krok 4 — Pogłębienie (10 min)
**Wariacje i eksperymenty:**
- W terminalu naciśnij strzałkę w górę → poprzednia komenda się pojawia (oszczędzasz pisanie)
- `Ctrl+C` — przerwij działający program (przydatne przy nieskończonych pętlach)
- `python3` bez argumentów → tryb interaktywny; `exit()` → wyjście

**Eksperyment "co jeśli":**
- Co zwróci `ls` w pustym katalogu?
- Co `cd` bez argumentu? (na macOS: katalog domowy)
- Co `python3 nieistniejacy.py`? (`No such file or directory`)

**Polecane skróty VS Code** (krótka demonstracja):
- `Cmd+S` — zapisz (KAŻDORAZOWO przed uruchomieniem)
- `Cmd+P` — szybkie otwarcie pliku po nazwie
- `Cmd+/` — zakomentuj/odkomentuj linię

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "swoboda w terminalu". Sugerowane zadania:
- 🔥 Utwórz katalog `eksperymenty/`, w nim plik `proba.py` z print, uruchom
- ⭐ Zrób to bez używania myszy — tylko klawiatura (cd, mkdir, edytor z linii poleceń)
- ⚡ Napisz w pliku 5 print-ów, uruchom — zwróć uwagę, w jakiej kolejności się pokazują (sekwencyjnie!)

## Pułapki
- **Wbudowany terminal VS Code w innym katalogu niż myślisz** — sprawdzaj `pwd`.
- **Zapomniany Cmd+S** — uruchamiasz starą wersję pliku.
- **Backslash `\` zamiast slasha `/` w ścieżkach** — to Windows; na macOS/Linux używamy `/`.
- **`cd` po angielsku, w jednej linii** — uczeń może próbować `cd kurs/zadania` jako dwie komendy.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **VS Code zamiast PyCharm** — źródłowy materiał poleca PyCharm. W 2026 dla początkujących VS Code jest lżejszy, darmowy w pełni, lepiej zintegrowany z Claude Code / AI.
- **Wbudowany terminal VS Code** to ogromna pomoc — nie trzeba mieć osobnego okna Terminal.app.
- **Rozszerzenie Python** od Microsoftu w VS Code — sprawdza wcięcia, podpowiada składnię, ma debugger.

## Notatki tutora
- **Nie zmuszaj do PyCharm**, jeśli uczeń woli VS Code (większość tak woli w 2026).
- Jeśli uczeń jest mocno przyzwyczajony do graficznego eksploratora plików — pokaż, że terminal jest **szybszy**, ale niech ma w zanadrzu też graficzny.
- Jeśli `Ctrl+C` nie działa — sprawdź czy terminal jest aktywny (nie edytor).
- Niech uczeń zerknie do `kurs/JAK-PISAC-KOD.md` — przypomni sobie cały workflow w sekcji 4.
