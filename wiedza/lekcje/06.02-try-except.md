# Lekcja 6.2 — Pierwsze `try`/`except`: pliki niezawodne

## Cel
Po lekcji uczeń:
- Pisze `try`/`except` do obsługi wyjątków
- Łapie konkretny typ wyjątku (`FileNotFoundError`, `ValueError`), nie wszystkie
- Wie, kiedy łapać wyjątek, a kiedy pozwolić mu "wybuchnąć"
- Używa `try`/`except`/`else`/`finally`

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Próbujesz otworzyć drzwi do mieszkania. Wkładasz klucz... a klucza nie ma. Co teraz?"

**Co chcesz usłyszeć:** kilka opcji — wracam po klucz, dzwonię do sąsiada, dzwonię do ślusarza. **Reagujesz** na problem zamiast się poddawać. To esencja obsługi błędów.

## Krok 2 — Mostek (5 min)
**Mostek:** "Programy też trafiają na problemy: brak pliku, zły format danych, błąd sieci. Python sygnalizuje to **wyjątkiem** (exception). Domyślnie program się **wywala**. Możemy jednak **przechwycić** wyjątek i zareagować."

**Minimalny przykład:**
```python
try:
    with open("nieistniejacy.txt", "r", encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print("Plik nie istnieje, ale program nie zginął!")
```

**Pytania:**
- "Co robi `try`?"
- "Co robi `except`?"
- "Co się stanie, jeśli plik **istnieje**?" → blok `except` zostaje pominięty.

## Krok 3 — Eksperyment (15 min)
1. **Bez try — pokaż katastrofę:**
```python
with open("brak.txt", "r") as f:
    print(f.read())
# FileNotFoundError: [Errno 2] No such file or directory: 'brak.txt'
# Program się ZATRZYMUJE!
```
2. **Z try — graceful:**
```python
try:
    with open("brak.txt", "r") as f:
        print(f.read())
except FileNotFoundError:
    print("Tworzę nowy plik...")
    with open("brak.txt", "w") as f:
        f.write("nowy plik\n")
```
3. **Konwersja stringa na int:**
```python
try:
    liczba = int(input("Podaj liczbę: "))
    print(f"Kwadrat: {liczba ** 2}")
except ValueError:
    print("To nie była liczba!")
```
4. **Wiele typów wyjątków:**
```python
try:
    a = int(input("Podaj liczbę: "))
    b = int(input("Podaj drugą: "))
    print(a / b)
except ValueError:
    print("Nieprawidłowa liczba")
except ZeroDivisionError:
    print("Nie dzielimy przez zero")
```

**Po każdym pytaj:** "Co Python zrobił? Który `except` zadziałał?"

## Krok 4 — Pogłębienie (15 min)

**`else` — wykonuje się gdy `try` przeszło BEZ wyjątku:**
```python
try:
    f = open("plik.txt", "r", encoding="utf-8")
except FileNotFoundError:
    print("brak pliku")
else:
    print(f.read())
    f.close()
```

**`finally` — wykonuje się ZAWSZE (z wyjątkiem lub bez):**
```python
try:
    print("próbuję")
    int("abc")
except ValueError:
    print("złapane")
finally:
    print("zawsze")  # wykona się
```

**Czytanie traceback (kluczowa umiejętność):**

Niech uczeń wywoła błąd i wspólnie przeczytajcie:
```
Traceback (most recent call last):
  File "test.py", line 5, in <module>
    print(int("abc"))
ValueError: invalid literal for int() with base 10: 'abc'
```
- **Ostatnia linia** = co się stało (`ValueError`)
- **Druga od końca** = gdzie (linia 5)
- **Najpierw od końca** czytaj!

**Hierarchia wyjątków (wzmiankuj):**
- `Exception` — bazowa klasa
- `ValueError`, `TypeError`, `FileNotFoundError`, `ZeroDivisionError`, `KeyError`, `IndexError` — najczęstsze

**Złapać wszystko (anty-idiom):**
```python
try:
    cosrobi()
except:           # ZŁE! łapie wszystko, w tym KeyboardInterrupt (Ctrl+C)
    pass

try:
    cosrobi()
except Exception: # lepiej, ale wciąż zwykle za szerokie
    pass
```
**Zasada:** łap **konkretne** wyjątki, nie wszystkie.

**Typowe błędy do sprowokowania:**
- Brak `:` po `try` lub `except` → SyntaxError.
- `except` bez typu — łapie wszystko (anty-idiom).
- Pętla z `try` w środku — sprawdź czy zachowuje się jak oczekujesz.

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "obsługa błędów". Sugerowane zadania:
- 🔥 Pytaj o liczbę. Jeśli użytkownik wpisze tekst — wypisz "to nie liczba", nie pozwól programowi się wywalić.
- ⭐ Funkcja `bezpieczne_dzielenie(a, b)` zwracająca `a / b` lub `None` jeśli `b == 0`. Użyj try/except.
- ⚡ "Czytaj plik lub stwórz" — jeśli `dane.txt` istnieje, wypisz zawartość. Jeśli nie — stwórz z domyślną treścią i wypisz.

## Pułapki
- **Łapanie wszystkiego (`except:`)** ukrywa prawdziwe błędy. Łap konkretne.
- **Łapanie `Exception`** to anty-idiom w 90% przypadków.
- **Cisza po `except`** (`except: pass`) — najgorszy nawyk. Zawsze przynajmniej zapisz log albo wypisz coś.
- **Nadużywanie try/except** zamiast walidacji — jeśli możesz **sprawdzić** zamiast łapać, sprawdź. Np. `if path.exists(): ...` zamiast łapać `FileNotFoundError` (ale to konwencja, oba są legalne — "EAFP" vs "LBYL").
- **`try` jako kontrola przepływu** — anty-idiom. Wyjątki są drogie.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **Lepsze tracebacki (3.11+, 3.13)** — Python pokazuje znaczek `^^^^` pod fragmentem linii z błędem oraz koloruje (3.13). Powiedz uczniowi: nie zniechęcaj się długim tekstem — czytaj od końca.
- **Sugestie typu "Did you mean...?"** (3.12+): `NameError: name 'lne' is not defined. Did you mean: 'len'?`. Zawsze sprawdzaj sugestię.
- **`ExceptionGroup` i `except*`** (3.11+) — zaawansowane, wzmianka tylko w module 8.
- **`except` bez nawiasów** (3.14, PEP 758): `except ValueError, TypeError:` — wzmianka, nie używaj jeszcze w lekcjach.

## Notatki tutora
- **Czytanie traceback to umiejętność #1** dla każdego programisty. Zatrzymaj się tu na chwilę, pokaż 2-3 różne błędy, niech uczeń sam je przeczyta.
- **Pełna obsługa wyjątków + własne wyjątki** — moduł 8. Tu tylko podstawy "żeby program nie umierał".
- Pokaż, że try/except jest dla **niespodziewanych** sytuacji (brak pliku, błędne dane od użytkownika), NIE dla normalnej logiki (`if x > 0: ...` zamiast try/except).
