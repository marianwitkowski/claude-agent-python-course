# Lekcja 4.2 — Krotki: kiedy zamiast listy

## Cel
Po lekcji uczeń:
- Tworzy krotkę: `(1, 2, 3)`
- Wie, że krotka jest **niemutowalna** (immutable)
- Rozumie, kiedy krotka lepsza od listy (stałe zestawy, wiele wartości z funkcji)
- Używa unpackingu: `x, y = (3, 4)`

## Krok 1 — Zakotwiczenie (3 min)
**Pytanie wejściowe:**
> "Jaka jest różnica między listą zakupów na lodówce a parą współrzędnych na mapie (np. szerokość, długość geograficzna)?"

**Co chcesz usłyszeć:** lista zakupów się zmienia, współrzędne jednego punktu — nie. Krotka to taka "zamrożona" lista.

## Krok 2 — Mostek (5 min)
**Mostek:** "W Pythonie mamy dwa rodzaje 'pojemników na sekwencję wartości': **lista** (zmienna) i **krotka** (niezmienna). Krotka tworzona nawiasami `()` zamiast `[]`."

**Minimalny przykład:**
```python
punkt = (3, 4)
print(punkt[0])  # 3
# punkt[0] = 5  # BŁĄD! TypeError
```

**Pytania:**
- "Jaka jest podstawowa różnica od listy?"
- "Po co nam coś, czego nie można zmienić?" → bezpieczeństwo, jasna intencja "to stałe".

## Krok 3 — Eksperyment (10 min)
1. `(3, 4)` — krotka 2-elementowa
2. `("Anna", 30, "Warszawa")` — krotka 3-elementowa
3. `(5,)` — krotka 1-elementowa (przecinek obowiązkowy!). Bez przecinka `(5)` to **liczba w nawiasach**, nie krotka.
4. `()` — pusta krotka
5. **Indeksowanie i slicing — działa jak w liście:** `punkt[0]`, `punkt[1:]`
6. **Próba modyfikacji:** `punkt[0] = 99` → TypeError
7. **`len(punkt)`** → działa
8. **`for x in punkt:`** → działa

**Po każdym pytaj:** "Co tu działa tak samo jak lista? Co inaczej?"

## Krok 4 — Pogłębienie (10-15 min)

**Unpacking — silny idiom Pythona:**
```python
punkt = (3, 4)
x, y = punkt
print(x, y)  # 3 4
```

Działa też w drugą stronę:
```python
para = "Anna", 30  # nawiasy opcjonalne
print(type(para))  # tuple
```

**Wymiana zmiennych — klasyczny przykład:**
```python
a, b = 5, 10
a, b = b, a
print(a, b)  # 10 5 — bez tymczasowej zmiennej!
```

**Krotka jako "wiele wartości naraz" z funkcji** (wzmianka, funkcje w module 5):
```python
def podziel(a, b):
    return a // b, a % b   # zwraca krotkę

iloraz, reszta = podziel(17, 5)
print(iloraz, reszta)  # 3 2
```

**Kiedy krotka vs lista:**
| Sytuacja                            | Wybór   |
| ----------------------------------- | ------- |
| Zbiór wartości zmieniający się      | lista   |
| Stała współrzędna / dane wiersza    | krotka  |
| Wiele zwracanych wartości z funkcji | krotka  |
| Klucze do słownika (lekcja 4.3)     | krotka  |
| Iterujesz, ale nie modyfikujesz     | krotka — sygnał intencji |

**Typowe błędy do sprowokowania:**
- `(5)` — myślisz że to krotka, a to liczba w nawiasach. Pokaż `type((5))` → int. Pokaż `type((5,))` → tuple.
- Próba `.append` na krotce → AttributeError (krotka nie ma `append`).
- `a, b = (1, 2, 3)` → ValueError (3 elementy, 2 zmienne).

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "krotki w praktyce". Sugerowane zadania:
- 🔥 Stwórz krotkę 3 współrzędnych RGB koloru (np. czerwony = (255, 0, 0)). Wypisz każdą składową.
- ⭐ Lista 5 osób, każda jako krotka (imie, wiek). Iteruj — wypisz "X ma Y lat".
- ⚡ Funkcja `dziel_z_reszta(a, b)` zwracająca krotkę (iloraz, reszta). Wywołaj kilka razy, użyj unpackingu.

## Pułapki
- **Krotka 1-elementowa wymaga przecinka:** `(5,)`, nie `(5)`.
- **Nie ma `append`, `pop`, `sort`** — krotka jest niemutowalna.
- **Można zrobić `nowa = (1, 2) + (3, 4)`** — to nie modyfikacja, tylko nowa krotka.
- **Krotka zawierająca listę jest "częściowo modyfikowalna"** — sama krotka nie, ale lista wewnątrz tak. Zaawansowane, wzmiankuj.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **Type hints na krotkach** (3.9+): `def f(p: tuple[int, int]) -> tuple[float, float]:`. Wzmianka, nie wymuszaj.
- **`NamedTuple` / `dataclass`** — alternatywa dla krotek "z nazwanymi polami". Dotkniemy w module 7.

## Notatki tutora
- **Nie poświęcaj zbyt dużo** czasu na krotki — to lekcja "krótsza" z założenia. 25-35 min wystarczy.
- **Najważniejszy idiom**: wiele zwracanych wartości + unpacking. Tego uczeń użyje w prawdziwym kodzie.
- Jeśli uczeń pyta "to po co tej krotki, skoro lista robi to samo i więcej?" — odpowiedz: **intencja**. Czytając kod widzisz `point = (3, 4)` i wiesz, że to **stała para**. Czytając `point = [3, 4]` myślisz "może to się zmieni". Komunikacja z innymi (i przyszłym sobą).
