# Lekcja 3.1 — `if`/`elif`/`else` i operatory logiczne

## Cel
Po lekcji uczeń:
- Pisze warunki: `if x > 5: ...`
- Używa `elif`, `else` do alternatywnych ścieżek
- Łączy warunki: `and`, `or`, `not`
- Rozumie, że Python działa "linia po linii" — i warunki to **rozgałęzienie**

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Kiedy bierzesz parasol, wychodząc z domu? Sformułuj regułę, najprostszą jak się da."

**Co chcesz usłyszeć:** "JEŚLI pada (lub może padać), TO biorę parasol. INACZEJ nie biorę." Naprowadzaj na strukturę "jeśli...to..." bez słowa "warunek".

## Krok 2 — Mostek (5 min)
**Mostek:** "Taka reguła to **warunek**. W Pythonie zapisujemy ją słowem `if`. Komputer sprawdza warunek i wykonuje różne kroki w zależności od wyniku."

**Minimalny przykład:**
```python
pada = True
if pada:
    print("Bierz parasol")
else:
    print("Bez parasola")
```

**Pytania:**
- "Co Python sprawdza w 2. linii?"
- "Czemu są wcięcia (spacje) przed `print`?"

Wprowadź pojęcie: **wcięcie** (indentation) — Python używa wcięć zamiast `{` `}` jak inne języki. To **fundament składni**.

## Krok 3 — Eksperyment (15 min)
1. `wiek = 18; if wiek >= 18: print("pełnoletni")`
2. Dodaj `else: print("niepełnoletni")` — testuj z różnymi wiekami
3. **`elif`** — wiele alternatyw:
```python
ocena = 4
if ocena == 5:
    print("celująca")
elif ocena == 4:
    print("bardzo dobra")
elif ocena == 3:
    print("dobra")
else:
    print("inna")
```
4. **Operatory porównania:** `==`, `!=`, `<`, `>`, `<=`, `>=`. Niech uczeń sam wypróbuje każdy.

**Po każdym pytaj:** "Spodziewałeś się tego wyniku? Co byś musiał zmienić, żeby weszło w inną gałąź?"

## Krok 4 — Pogłębienie (15-20 min)

**Operatory logiczne — `and`, `or`, `not`:**
```python
wiek = 25
ma_prawo_jazdy = True
if wiek >= 18 and ma_prawo_jazdy:
    print("Może prowadzić")
```

**Tabela prawdy do eksperymentu:**
- `True and True` → True
- `True and False` → False
- `True or False` → True
- `False or False` → False
- `not True` → False

Pytanie: "Kiedy `and` zwraca True? A `or`?"

**Wartości "prawdziwe i fałszywe" (truthy/falsy):**
- `False`, `0`, `0.0`, `""`, `[]`, `None` → traktowane jako **fałsz**
- Wszystko inne → **prawda**
```python
if "":  # fałsz
    print("nie wypisze")
if "anna":  # prawda
    print("wypisze")
```

**Zagnieżdżone if:**
```python
if pogoda == "deszcz":
    if temperatura < 10:
        print("Bierz parasol i ciepłą kurtkę")
    else:
        print("Tylko parasol")
```

**Typowe błędy do sprowokowania:**
- `if x = 5:` — `=` zamiast `==` → SyntaxError. Wytłumacz różnicę.
- Brak `:` na końcu linii z `if` — SyntaxError.
- **Mieszanie spacji z tabami** w wcięciach — IndentationError. Powiedz uczniowi: zostaw VS Code, on robi 4 spacje automatycznie.
- `if pora == "rano" or "wieczór":` — to **zawsze True**! Bo `"wieczór"` to truthy. Trzeba: `if pora == "rano" or pora == "wieczór":` (lub `if pora in ("rano", "wieczór"):`).

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "decyzje". Sugerowane zadania:
- 🔥 Zapytaj o wiek, wypisz "pełnoletni" lub "niepełnoletni"
- ⭐ "Czy parzysta?" — zapytaj o liczbę, wypisz "parzysta" lub "nieparzysta" (użyj `%`)
- ⚡ Kalkulator BMI: wzrost (m) i waga (kg), oblicz, wypisz kategorię (niedowaga/norma/nadwaga). Skala: <18.5 niedowaga, 18.5-25 norma, >25 nadwaga.

## Pułapki
- **`=` vs `==`** — najczęstszy błąd. `=` przypisuje, `==` porównuje.
- **Brak `:` na końcu warunku** — Python wymaga.
- **Złe wcięcie** — kod "wewnątrz" if musi mieć większe wcięcie. Mieszanie spacji/tabów = problem.
- **`if x == 5 or 6:`** — to ZAWSZE True (bo 6 to truthy). Pisz `if x == 5 or x == 6:` lub `if x in (5, 6):`.
- **`and` ma wyższy priorytet niż `or`** — bezpiecznie pisz nawiasy: `(a and b) or c`.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **`match`/`case` (3.10+)** — wzmiankuj na końcu lekcji jako "skrót do długich łańcuchów elif":
```python
match dzien:
    case "pn" | "wt" | "śr" | "czw" | "pt":
        print("dzień roboczy")
    case "sob" | "niedz":
        print("weekend")
    case _:
        print("nieznany")
```
Ale: **nie wprowadzaj jako standard**, tylko jako "ciekawostka, dojdziemy w przyszłości". Klasyczny `if/elif/else` to baza.

## Notatki tutora
- **Wcięcia to fundament Pythona** — poświęć tu czas. Niech uczeń sam zobaczy `IndentationError`.
- Jeśli uczeń pisze `if (x > 5):` z nawiasami (jak w C) — pozwól, ale powiedz że to **anty-idiom** Pythona. Pisz bez nawiasów.
- **Konwencja: zawsze 4 spacje** (PEP 8). VS Code z Python extension robi to za ucznia.
- Nie wprowadzaj **operatora trójargumentowego** (`a if cond else b`) — jeszcze nie. Może w module 5.
