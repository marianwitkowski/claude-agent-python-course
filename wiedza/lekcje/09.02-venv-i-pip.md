# Lekcja 9.2 — `venv` i `pip` — zarządzanie pakietami

## Cel
Po lekcji uczeń:
- Tworzy wirtualne środowisko: `python3 -m venv .venv`
- Aktywuje i deaktywuje (`source .venv/bin/activate`, `deactivate`)
- Instaluje pakiety: `pip install <nazwa>`
- Zapisuje listę: `pip freeze > requirements.txt`
- Wie o `uv` jako szybszej alternatywie (2026)

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Masz w domu różne projekty, każdy wymaga innych narzędzi. Czy trzymasz wszystko razem w jednym pudle, czy oddzielne pudła dla każdego projektu?"

**Co chcesz usłyszeć:** oddzielne — w pudle dla projektu A nie chcesz narzędzi B, które mogą się gryźć. Tak samo z bibliotekami Pythona — **wirtualne środowisko** to "pudło" tego projektu.

## Krok 2 — Mostek (5 min)
**Mostek:** "**Wirtualne środowisko (venv)** to izolowana 'lokalna instalacja Pythona' dla **jednego projektu**. Pakiety instalowane w venv nie wpływają na inne projekty. Bez tego — wszystko w globalnym Pythonie, konflikty wersji."

**Po co venv?**
- Projekt A wymaga `requests==2.28`, projekt B `requests==2.31` — bez venv konflikt.
- Reproducibility — `requirements.txt` mówi dokładnie co zainstalować.
- Czystość — globalny Python pozostaje "czysty".

## Krok 3 — Eksperyment (15-20 min)

**1. Stwórz katalog projektu:**
```bash
mkdir moj-projekt
cd moj-projekt
```

**2. Stwórz venv:**
```bash
python3 -m venv .venv
```
Powstanie katalog `.venv/` (zwykle dodaje się do `.gitignore` — uczeń pewnie jeszcze nie zna gita, ale wspomnij).

**3. Aktywuj** (komenda zależy od systemu):

**macOS / Linux:**
```bash
source .venv/bin/activate
```

**Windows PowerShell:**
```powershell
.venv\Scripts\Activate.ps1
```

Jeśli PowerShell rzuca błąd "running scripts is disabled" — wykonaj **jednorazowo**:
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

**Windows cmd.exe:**
```cmd
.venv\Scripts\activate.bat
```

Zauważ — prompt terminala teraz pokazuje `(.venv)` z przodu. To znak że jesteś w venv. Działa tak samo we wszystkich systemach.

**4. Sprawdź:**

macOS / Linux:
```bash
which python3   # powinno wskazywać .venv/bin/python3
pip list        # tylko pip + setuptools (czyste środowisko)
```

Windows PowerShell:
```powershell
Get-Command python   # powinno wskazywać .venv\Scripts\python.exe
pip list
```

**5. Zainstaluj pakiet:**
```bash
pip install requests
pip list        # teraz: pip, requests, certifi, ...
```

**6. Użyj w pliku `test.py`:**
```python
import requests
r = requests.get("https://api.github.com")
print(r.status_code)
print(r.json()["current_user_url"])
```

**7. Zapisz wymagania:**
```bash
pip freeze > requirements.txt
cat requirements.txt
# requests==2.31.0
# certifi==2024.2.2
# ...
```

**8. Deaktywuj venv:**
```bash
deactivate
```

**9. Reaktywacja w przyszłej sesji:**
```bash
source .venv/bin/activate
```

**10. Odtwarzanie środowiska na nowej maszynie:**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**Po każdym kroku pytaj:** "Co się zmieniło w terminalu? Co `which python3` pokazuje teraz?"

## Krok 4 — Pogłębienie (15 min)

### `uv` — nowoczesna alternatywa (2026):

```bash
pip install uv     # instalacja uv
# Tworzenie venv (10x szybciej niż python3 -m venv):
uv venv

# Instalacja pakietów (znacznie szybciej niż pip):
uv pip install requests
uv pip install -r requirements.txt
```
W ekosystemie Pythona 2026 `uv` (od Astral, ci sami co `ruff`) staje się standardem. Polecaj nowym projektom.

### `pyproject.toml` — nowy standard:

Zamiast `requirements.txt` można używać `pyproject.toml`:
```toml
[project]
name = "moj-projekt"
version = "0.1.0"
dependencies = [
    "requests>=2.30",
    "pandas",
]

[project.optional-dependencies]
dev = ["pytest", "ruff"]
```

Instalacja:
```bash
pip install -e .          # editable mode, projekt jako pakiet
pip install -e ".[dev]"   # plus dev deps
```

### `pip` — często używane komendy:
- `pip install <pakiet>` — zainstaluj
- `pip install <pakiet>==1.2.3` — konkretna wersja
- `pip install <pakiet>>=1.2,<2.0` — przedział
- `pip install -U <pakiet>` — update do najnowszej
- `pip uninstall <pakiet>` — usuń
- `pip show <pakiet>` — info o pakiecie
- `pip list` — co zainstalowane
- `pip freeze` — wersje w formacie requirements.txt

### Problem na macOS/Linux 3.12+:

Jeśli wpiszesz `pip install` BEZ aktywnego venv, możesz dostać:
```
error: externally-managed-environment
```
To **ochrona** systemu przed psuciem. Zawsze instaluj w venv.

### `pipx` — narzędzia CLI:
Gdy chcesz zainstalować narzędzie (np. `ruff`, `black`) **globalnie**, ale w izolacji:
```bash
pipx install ruff
pipx install black
```
Każde dostaje swój venv "pod maską". Świetne dla CLI.

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "venv i pip". Sugerowane zadania:
- 🔥 Stwórz nowy katalog, venv, zainstaluj `requests`, napisz skrypt pobierający `https://httpbin.org/uuid`, wypisz odpowiedź.
- ⭐ W venv zainstaluj `pytest` i `requests`. Stwórz `requirements.txt`. Usuń venv, odtwórz z requirements. Sprawdź czy wszystko działa.
- ⚡ Stwórz `pyproject.toml` z 2 dependencies. Zainstaluj `pip install -e .`. Spróbuj zaimportować w plik `main.py`.

## Pułapki
- **Zapomniana aktywacja venv** — `pip install` instaluje globalnie. Sprawdzaj prompt `(.venv)`.
- **`pip3` vs `pip`** — w venv `pip` zawsze wskazuje na właściwy. Globalnie czasem `pip3` jest potrzebne.
- **`.venv` w gitignore** — venv ma być **lokalne**, nie w repo. Dodaj `.venv/` do `.gitignore`.
- **`requirements.txt` bez wersji** — `pip freeze` powinno dawać wersje. Bez wersji = brak reprodukowalności.
- **Mieszanie globalnego pythona z venv** — sprawdź `which python3` jeśli coś dziwnego.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **`uv`** to ~10–100× szybszy `pip`. Polecaj nowym projektom.
- **`pyproject.toml`** to standard (PEP 621). `setup.py` to historia.
- **`pipx`** dla narzędzi CLI — `ruff`, `black`, `mypy`, `httpie`.
- **Pliki lock** (`requirements.lock`, `uv.lock`) — pełna reproducibility. Zaawansowane.

## Notatki tutora
- **Pierwsza instalacja `requests`** to "wow moment" — uczeń widzi że MOŻE używać kodu innych.
- **Aktywacja venv jest myląca** — niech uczeń zrobi to 2-3 razy, aż wejdzie w mięśnie palców.
- **Nie wprowadzaj** poetry, pipenv, conda — to alternatywne ekosystemy. Trzymaj się `venv` + `pip` lub `uv`.
- Jeśli uczeń pyta o `conda` (Anaconda) — wytłumacz: to alternatywa popularna w data science, ale dla początku trzymajmy się stdlib `venv`.
