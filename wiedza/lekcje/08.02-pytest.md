# Lekcja 8.2 — Testy jednostkowe z `pytest`

## Cel
Po lekcji uczeń:
- Instaluje `pytest` (`pip install pytest`)
- Pisze prosty test: `def test_cos(): assert ...`
- Uruchamia testy z terminala: `pytest`
- Używa `pytest.raises` do testowania wyjątków
- Wie, jak organizować testy (`tests/test_xxx.py`)

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Kupiłeś krzesło z IKEA. Przed użyciem — czy potrząsasz nim, sprawdzasz czy wszystkie śruby siedzą? Po co?"

**Co chcesz usłyszeć:** sprawdzasz **czy działa zgodnie z oczekiwaniem**, zanim usiądziesz. Po **każdej** zmianie (np. po przeprowadzce). Tak działają testy w kodzie.

## Krok 2 — Mostek (5 min)
**Mostek:** "Test to mały program, który **uruchamia twój kod z konkretnymi danymi** i sprawdza, czy wynik jest taki, jakiego oczekujesz. Jeśli oczekiwany = rzeczywisty → test przechodzi. Jeśli nie → test wyłapuje błąd."

**Po co testy?**
- Łapią błędy **automatycznie**, gdy ty zmieniasz kod
- Dokumentują "jak ma działać funkcja"
- Pozwalają zmieniać kod **bez strachu**

**Minimalny przykład:**

`mat.py`:
```python
def dodaj(a, b):
    return a + b
```

`test_mat.py`:
```python
from mat import dodaj

def test_dodaj_dodatnie():
    assert dodaj(2, 3) == 5

def test_dodaj_ujemne():
    assert dodaj(-1, -1) == -2
```

Uruchomienie w terminalu: `pytest`. Pytest **sam** znajdzie testy w plikach `test_*.py`.

## Krok 3 — Eksperyment (15-20 min)

1. **Instalacja:**
```bash
pip install pytest
```

2. **Stwórz funkcję do przetestowania (`kalkulator.py`):**
```python
def dodaj(a, b):
    return a + b

def podziel(a, b):
    if b == 0:
        raise ValueError("nie dzielimy przez zero")
    return a / b
```

3. **Stwórz `test_kalkulator.py`:**
```python
from kalkulator import dodaj, podziel
import pytest

def test_dodaj_dodatnie():
    assert dodaj(2, 3) == 5

def test_dodaj_zera():
    assert dodaj(0, 0) == 0

def test_dodaj_ujemne():
    assert dodaj(-5, 3) == -2

def test_podziel_dziala():
    assert podziel(10, 2) == 5

def test_podziel_przez_zero():
    with pytest.raises(ValueError):
        podziel(10, 0)
```

4. **Uruchom: `pytest` w katalogu z testami.**

5. **Zobacz output:**
```
test_kalkulator.py .....                          [100%]
========= 5 passed in 0.02s ========
```

6. **Eksperyment: zepsuj funkcję** (`dodaj` zwraca `a + b + 1`), uruchom — pytest pokaże **który** test padł, z **konkretnym wynikiem oczekiwany vs rzeczywisty**.

7. **Verbose mode:** `pytest -v` (każdy test z osobna).

## Krok 4 — Pogłębienie (15 min)

**Testowanie wyjątków:**
```python
def test_podziel_przez_zero_komunikat():
    with pytest.raises(ValueError, match="nie dzielimy"):
        podziel(10, 0)
```

**Parametryzacja (jedno z najmocniejszych narzędzi pytest):**
```python
@pytest.mark.parametrize("a, b, oczekiwane", [
    (2, 3, 5),
    (0, 0, 0),
    (-5, 3, -2),
    (100, 200, 300),
])
def test_dodaj(a, b, oczekiwane):
    assert dodaj(a, b) == oczekiwane
```
Jeden test → 4 uruchomienia z różnymi danymi.

**Fixture (przygotowanie danych przed testem):**
```python
@pytest.fixture
def przykladowa_lista():
    return [3, 1, 4, 1, 5, 9, 2, 6]

def test_max(przykladowa_lista):
    assert max(przykladowa_lista) == 9

def test_dlugosc(przykladowa_lista):
    assert len(przykladowa_lista) == 8
```

**`unittest` (klasyka, historia):**
```python
import unittest

class TestKalkulator(unittest.TestCase):
    def test_dodaj(self):
        self.assertEqual(dodaj(2, 3), 5)

    def test_podziel_przez_zero(self):
        with self.assertRaises(ValueError):
            podziel(10, 0)
```
Pokaż dla porównania — **pytest jest krótszy**. Wzmiankuj, że `unittest` zobaczy w starszych kodach.

**Typowe błędy do sprowokowania:**
- Nazwa pliku bez `test_` → pytest nie znajdzie.
- Nazwa funkcji bez `test_` → też nie znajdzie.
- `assert dodaj(2,3) == 6` (celowy błąd) — pokaż jak pytest pięknie pokazuje co poszło źle.

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "pierwsze testy". Sugerowane zadania:
- 🔥 Funkcja `kwadrat(x)`. Test: `test_kwadrat_dodatnich`, `test_kwadrat_zera`, `test_kwadrat_ujemnych`.
- ⭐ Klasa `Konto` z metodami `wplac`, `wyplac`. Test: wpłata, wypłata, brak środków (z `pytest.raises`).
- ⚡ Funkcja `oblicz_VAT(netto, stawka=0.23)`. Test parametryzowany z 5 zestawami danych. Plus test `pytest.raises` dla ujemnej stawki.

## Pułapki
- **Nazwa pliku/funkcji musi zaczynać się od `test_`** — inaczej pytest pominie.
- **Test bez `assert`** — przechodzi domyślnie, nawet jeśli funkcja nic nie sprawdza. **Zawsze `assert`.**
- **Testowanie wielu rzeczy w jednym teście** — gdy padnie pierwszy assert, reszta nie wykonuje się. Lepiej małe, oddzielne testy.
- **Mockowanie/zewnętrzne zasoby** — testy mają być **szybkie** i **niezależne** od sieci/bazy. Mockowanie to temat zaawansowany.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **`pytest` to standard 2026.** `unittest` jest w stdlib, ale w prawie każdym profesjonalnym projekcie używa się pytest.
- **Coverage** (`pip install pytest-cov`) — sprawdza ile linii kodu pokrytych testami: `pytest --cov=kalkulator`. Cel: >80% pokrycia dla biznesu, 100% to często overkill.
- **`pytest-xdist`** — uruchamianie testów równolegle: `pytest -n auto`.
- **`hypothesis`** — property-based testing, bardzo potężne, dla zaawansowanych: generuje setki przypadków testowych automatycznie.

## Notatki tutora
- **Pierwszy test, który ZADZIAŁA, to przełomowy moment** — uczeń poczuje "to zmienia jak piszę kod".
- **Pokaż czerwone-zielone-refactor** — celowo zepsuj funkcję, niech test padnie, niech uczeń naprawi.
- **`pytest.raises` jako paradygmat** — uczenie wyjątków w testach to ważne.
- **Nie wprowadzaj `mock`, `MagicMock`** — to zaawansowane.
