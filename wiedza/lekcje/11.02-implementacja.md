# Lekcja 11.2 — Implementacja krok po kroku

## Cel
Po lekcji uczeń:
- Tworzy strukturę projektu (`pyproject.toml`, `src/`, `tests/`)
- Implementuje funkcjonalności **jedna po drugiej** z TODO
- Po każdej feature: commit (jeśli używa Git), test ręczny
- Trzyma się **MVP** — nie dodaje rzeczy "na zapas"

## Krok 1 — Zakotwiczenie (3 min)
**Pytanie wejściowe:**
> "Idziesz po zakupy z listą 10 rzeczy. Czy zbierasz wszystko naraz, mieszając w koszyku? Czy robisz po kolei i odhaczasz?"

**Co chcesz usłyszeć:** po kolei i odhaczasz. To samo z projektem — **jedna feature naraz, sprawdź, odhacz, następna**.

## Krok 2 — Mostek (5 min)
**Mostek:** "Implementacja to **wykonywanie TODO** z lekcji 11.1. Nie skacz między feature'ami — skończ jedno, sprawdź że działa, **dopiero potem** następne. To dyscyplina."

**Reguła:** "Jeśli skończyłeś jedną feature, **odhacz** w TODO i opcjonalnie zrób commit. Nie zostawiaj 5 niedokończonych."

### Etap 3: Pierwsza funkcjonalność z TODO

Na przykładzie TODO-CLI: implementacja `add`.

`src/main.py`:
```python
import sys
import json
from pathlib import Path

TODO_FILE = Path("todo.json")

def wczytaj() -> list:
    if not TODO_FILE.exists():
        return []
    return json.loads(TODO_FILE.read_text(encoding="utf-8"))

def zapisz(zadania: list) -> None:
    TODO_FILE.write_text(
        json.dumps(zadania, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )

def dodaj(tekst: str) -> None:
    zadania = wczytaj()
    nowe_id = max([z["id"] for z in zadania], default=0) + 1
    zadania.append({"id": nowe_id, "tekst": tekst, "zrobione": False})
    zapisz(zadania)
    print(f"Dodano #{nowe_id}: {tekst}")

def main():
    if len(sys.argv) < 2:
        print("Użycie: todo.py <add|list|done|remove> ...")
        sys.exit(1)

    komenda = sys.argv[1]
    if komenda == "add":
        if len(sys.argv) < 3:
            print("Brak tekstu zadania")
            sys.exit(1)
        dodaj(" ".join(sys.argv[2:]))
    else:
        print(f"Nieznana komenda: {komenda}")
        sys.exit(1)

if __name__ == "__main__":
    main()
```

Test:
```bash
python3 src/main.py add "kup mleko"
python3 src/main.py add "wynieś śmieci"
cat todo.json
```

### Etap 4: Test jednostkowy

`tests/test_main.py`:
```python
from pathlib import Path
import json
from src import main

def test_dodaj(tmp_path, monkeypatch):
    plik = tmp_path / "test.json"
    monkeypatch.setattr(main, "TODO_FILE", plik)

    main.dodaj("zadanie 1")
    main.dodaj("zadanie 2")

    dane = json.loads(plik.read_text(encoding="utf-8"))
    assert len(dane) == 2
    assert dane[0]["tekst"] == "zadanie 1"
    assert dane[1]["id"] == 2
```

Uruchom: `pytest`.

### Etap 5: Iteracja po kolejnych TODO

Powtarzaj **dla każdej feature**:
1. Wybierz najmniejsze TODO
2. Zaimplementuj
3. Przetestuj ręcznie
4. Napisz test (jeśli pasuje)
5. Odhacz w TODO
6. (opcjonalnie) `git commit -m "feature: ..."`
7. Następne TODO

## Krok 4 — Pogłębienie (10 min)

**Dobre nawyki implementacji:**

1. **Najpierw szkielet** — pusta funkcja, `pass`, sprawdź że plik się importuje
2. **Najprostsza wersja** — bez walidacji, bez błędów, bez optymalizacji
3. **Test ręczny** — uruchom, sprawdź że robi co miało
4. **Następnie:** walidacja danych wejściowych
5. **Następnie:** obsługa błędów (try/except)
6. **Na końcu:** czystość kodu, refactoring

**Co odróżnia początkującego od średniozaawansowanego:**
- Początkujący pisze 200 linii naraz, potem 3h debuguje
- Średniozaawansowany pisze 20 linii, testuje, dodaje 20

**Kod się rozrasta — kiedy podzielić na pliki?**
- `main.py` > 200 linii → podziel
- Logika biznesowa → osobny plik (`src/logika.py`)
- I/O (pliki, sieć) → osobny plik (`src/io.py`)
- Modele danych → osobny plik (`src/models.py`)

**Typowe błędy:**
- **Wszystko w jednym pliku** — działa, ale po 500 liniach koszmar
- **Implementacja "na zapas"** — robisz pole `priority` w TODO, choć MVP go nie potrzebuje
- **Brak testów** — przy 5. feature coś się psuje i nie wiesz co
- **Commit "WIP"** raz dziennie — lepiej granularne commity

## Krok 5 — Ćwiczenie
→ To **całe projektowanie** jest ćwiczeniem. Iteruj z uczniem:
- Każda sesja: 1-2 TODO ukończone
- Po każdej feature → przerwa, demo, refleksja
- Jeśli wpadasz na blocker > 30 min → debugger lub pytanie do agenta

## Pułapki
- **Programowanie "feature-zachłanne"** — chcesz wszystko naraz.
- **Brak commitów** — bug pojawia się i nie pamiętasz kiedy.
- **Pomijanie testów** — bo "działa".
- **Refactor przed MVP** — najpierw niech działa, potem upiększaj.
- **Hardcoded ścieżki / kluczy** — `/Users/marian/...` w kodzie. Używaj zmiennych środowiskowych albo argumentów.

## Notatki tutora
- **To jest długa lekcja** — może rozciągać się na wiele sesji. To OK.
- **Niech uczeń COMMITUJE często** — `git commit` co 20-30 linii. Granularność = bezpieczeństwo.
- **Sokratejskie review** — gdy uczeń pyta "czy to dobrze?", PYTAJ "co byś chciał żeby to robiło? czy robi?" zamiast oceniać.
- **Walcz z perfekcjonizmem** — "działa" > "piękne".
