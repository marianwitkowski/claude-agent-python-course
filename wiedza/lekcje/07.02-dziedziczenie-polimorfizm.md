# Lekcja 7.2 — Dziedziczenie i polimorfizm

## Cel
Po lekcji uczeń:
- Tworzy klasę dziedziczącą: `class Pies(Zwierze):`
- Wywołuje `super().__init__(...)` żeby zainicjować część "rodzica"
- Nadpisuje metodę w klasie potomnej
- Rozumie polimorfizm: ten sam interfejs, różne implementacje

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Pies, kot, krowa — to różne zwierzęta. Co mają wspólnego?"

**Co chcesz usłyszeć:** wszystkie są zwierzętami — mają wagę, wiek, rasę. Wszystkie jedzą, śpią. Ale każde **wydaje inny dźwięk**, każde może mieć **inne specyficzne cechy** (kot ma futro/krowa daje mleko).

To esencja **dziedziczenia**: wspólne rzeczy są w "rodzicu" (Zwierzę), specyficzne w "dziecku" (Pies, Kot).

## Krok 2 — Mostek (5 min)
**Mostek:** "**Dziedziczenie** to mechanizm, w którym klasa potomna **przejmuje** wszystko od klasy bazowej i może dodać swoje. Klasa Pies dziedziczy po Zwierze — dostaje wszystkie atrybuty i metody Zwierze, plus może dodać własne."

**Minimalny przykład:**
```python
class Zwierze:
    def __init__(self, imie, wiek):
        self.imie = imie
        self.wiek = wiek

    def przedstaw_sie(self):
        print(f"Jestem {self.imie}, mam {self.wiek} lat")

class Pies(Zwierze):
    def szczekaj(self):
        print(f"{self.imie}: Hau hau!")

burek = Pies("Burek", 3)
burek.przedstaw_sie()  # ODZIEDZICZONE z Zwierze
burek.szczekaj()       # własna metoda
```

**Pytania:**
- "Czy `Pies` ma własne `__init__`?" (nie — używa odziedziczonego)
- "Skąd Pies wie o `imie` i `wiek`?" (z dziedziczenia)

## Krok 3 — Eksperyment (15-20 min)

1. **Klasa bazowa + dwie pochodne:**
```python
class Zwierze:
    def __init__(self, imie):
        self.imie = imie

    def dzwiek(self):
        print("...")  # ogólny "żaden"

class Pies(Zwierze):
    def dzwiek(self):
        print("Hau hau!")  # NADPISANIE

class Kot(Zwierze):
    def dzwiek(self):
        print("Miau!")

z1 = Pies("Burek")
z2 = Kot("Mruczek")
z1.dzwiek()  # Hau hau!
z2.dzwiek()  # Miau!
```

2. **`super().__init__` — gdy chcesz dodać własne atrybuty:**
```python
class Pies(Zwierze):
    def __init__(self, imie, rasa):
        super().__init__(imie)   # wywołuje __init__ rodzica
        self.rasa = rasa         # i dodaje własny atrybut

burek = Pies("Burek", "mieszaniec")
print(burek.imie, burek.rasa)
```

3. **Polimorfizm w akcji:**
```python
zwierzeta = [Pies("Burek"), Kot("Mruczek"), Pies("Azor")]
for z in zwierzeta:
    z.dzwiek()   # Python sam wie, której metody użyć!
```
Niech uczeń się zatrzyma: TA SAMA pętla, RÓŻNE zachowania. **To jest polimorfizm.**

4. **`isinstance` — sprawdzenie typu:**
```python
print(isinstance(burek, Pies))      # True
print(isinstance(burek, Zwierze))   # True — bo dziedziczy!
print(isinstance(burek, Kot))       # False
```

**Po każdym pytaj:** "Co Python zrobił? Czego się spodziewałeś?"

## Krok 4 — Pogłębienie (15 min)

**Praktyczny przykład — klasy z prawdziwego życia:**
```python
class Figura:
    def __init__(self, nazwa):
        self.nazwa = nazwa

    def pole(self):
        return 0  # bazowa — nadpiszą potomne

    def opis(self):
        return f"{self.nazwa}, pole: {self.pole()}"

class Kwadrat(Figura):
    def __init__(self, bok):
        super().__init__("Kwadrat")
        self.bok = bok

    def pole(self):
        return self.bok ** 2

class Kolo(Figura):
    def __init__(self, promien):
        super().__init__("Koło")
        self.promien = promien

    def pole(self):
        return 3.14 * self.promien ** 2

figury = [Kwadrat(5), Kolo(3), Kwadrat(2)]
for f in figury:
    print(f.opis())
```

Pokaż: `opis()` jest **w klasie bazowej**, ale gdy ją wywołasz, woła `self.pole()` — które jest **różne** dla każdej klasy potomnej. To moc polimorfizmu.

**Wiele dziedziczeń (wzmiankuj, nie wprowadzaj):**
```python
class A: pass
class B: pass
class C(A, B): pass   # dziedziczy po A i B
```
Komplikuje sprawę (MRO — Method Resolution Order). Wzmianka.

**Typowe błędy do sprowokowania:**
- Zapomniany `super().__init__(...)` — gdy próbujesz użyć atrybutu rodzica, dostajesz `AttributeError`.
- Nieprawidłowa składnia: `class Pies extends Zwierze:` (jak Java) — w Pythonie `class Pies(Zwierze):`.
- Wywołanie nadpisanej metody na klasie bazowej — `Zwierze.dzwiek(z1)` zadziała, ale to anty-idiom (po co?).

## Pułapki
- **Zapomniany `super().__init__()`** — atrybuty rodzica nie zostaną zainicjowane.
- **Modyfikacja klasy bazowej "po cichu"** — gdy ktoś inny używa twojej klasy bazowej, może się zepsuć.
- **Zbyt głębokie hierarchie** — `A → B → C → D → E` to znak, że trzeba przemyśleć projekt. Płytka hierarchia jest lepsza.
- **Dziedziczenie zamiast kompozycji** — czasem lepiej "ma w sobie" (`auto.silnik`) niż "jest" (`auto extends silnik`). Zaawansowane — wzmianka.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **`Protocol` — duck typing z type hints** (zaawansowane):
```python
from typing import Protocol

class Drukowalny(Protocol):
    def drukuj(self) -> None: ...
```
Nie wymaga dziedziczenia — wystarczy że klasa ma metodę `drukuj`. Wzmianka, dla początkującego pomiń.
- **`abc.ABC` — abstract base classes** — wzmianka, jeśli uczeń pyta o "wymuszanie implementacji metod w potomnych".

## Notatki tutora
- **Polimorfizm to AHA-MOMENT**. Pokaż pętlę po listach różnych obiektów z tym samym wywołaniem metody — efekt "magii".
- **`super().__init__(...)`** jest istotny — niech uczeń sprowokuje błąd, gdy go zapomni.
- **Nie wchodź w wielodziedziczenie**, MRO, mixiny — to dla doświadczonych.
- **Nie wprowadzaj jeszcze**: `@property`, `@classmethod`, `@staticmethod` — to 7.3 lub poza.
