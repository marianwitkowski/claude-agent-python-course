# Lekcja 5.3 — Scope, moduły i `import`

## Cel
Po lekcji uczeń:
- Rozumie scope: zmienna w funkcji nie istnieje poza funkcją
- Wie, czemu **nie modyfikujemy** globali z funkcji (i jak to robić jeśli musimy: `global`)
- Importuje moduł (`import math`) i używa funkcji (`math.sqrt(16)`)
- Tworzy własny moduł — `narzedzia.py` i importuje z innego pliku

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Jesteś w pokoju z notatnikiem. Wychodzisz. Kolega wchodzi. Czy widzi twój notatnik?"

**Co chcesz usłyszeć:** zależy. Notatnik na biurku w pokoju — tak. Notatnik w twoim plecaku — nie, wyszedł z tobą. To dwa **różne zakresy widoczności**.

## Krok 2 — Mostek (5 min)
**Mostek:** "W programowaniu też mamy zakresy: zmienne wewnątrz funkcji istnieją **tylko tam**. Po zakończeniu funkcji — znikają. To **scope lokalny**. Zmienne na poziomie pliku są **globalne** — widoczne wszędzie."

**Minimalny przykład:**
```python
def f():
    x = 10
    print(x)   # 10

f()
print(x)       # BŁĄD! NameError — x nie istnieje tutaj
```

**Pytanie:** "Czemu Python nie zobaczył `x`?"

## Krok 3 — Eksperyment (15 min)
1. **Lokalny vs globalny:**
```python
y = 100  # globalna

def f():
    y = 5  # NOWA lokalna, NIE modyfikuje globalnej!
    print(y)

f()           # 5
print(y)      # 100 — niezmienione!
```
2. **Czytanie globalnej z funkcji — DZIAŁA:**
```python
licznik = 0

def pokaz():
    print(licznik)  # widzi globalną

pokaz()  # 0
```
3. **Modyfikacja globalnej — wymaga `global`:**
```python
licznik = 0

def zwieksz():
    global licznik
    licznik += 1

zwieksz()
zwieksz()
print(licznik)  # 2
```
4. **Bez `global` — błąd:**
```python
licznik = 0

def zwieksz():
    licznik += 1   # UnboundLocalError!

zwieksz()
```
Bo Python widzi `licznik = ...` i myśli "tworzysz lokalną", a potem `licznik += 1` wymaga starej wartości — której nie ma.

**Po każdym pytaj:** "Co Python zrobił? Co poszło nie tak?"

## Krok 4 — Pogłębienie — moduły (15-20 min)

**Import — używanie cudzego kodu:**
```python
import math
print(math.sqrt(16))      # 4.0
print(math.pi)            # 3.14159...
print(math.floor(3.7))    # 3
```
`math` to **moduł** ze stdlib (standardowej biblioteki). Python ma ich setki.

**Import specyficznej funkcji:**
```python
from math import sqrt, pi
print(sqrt(16))   # bez prefiksu
print(pi)
```

**Alias:**
```python
import math as m
print(m.sqrt(16))
```

**Inne popularne moduły stdlib (wzmiankuj):**
- `random` — losowość: `random.randint(1, 10)`
- `datetime` — daty i czas
- `os` — system operacyjny
- `json` — pliki JSON

**Twój własny moduł — `narzedzia.py`:**

Stwórz plik `narzedzia.py`:
```python
def kwadrat(x):
    return x * x

def szescian(x):
    return x ** 3

PI = 3.14159
```

W innym pliku `main.py`:
```python
import narzedzia

print(narzedzia.kwadrat(5))   # 25
print(narzedzia.PI)
```

**Sprawdź razem z uczniem:** oba pliki muszą być w **tym samym katalogu**. Inaczej `ModuleNotFoundError`.

**Typowe błędy do sprowokowania:**
- `import matematyka` (literówka) → `ModuleNotFoundError`. Python sugeruje: "Did you mean: 'math'?" (3.12+).
- Brak `global` przed modyfikacją zmiennej globalnej → `UnboundLocalError`.
- Próba użycia `x` poza funkcją gdzie była zdefiniowana → `NameError`.

## Pułapki
- **Modyfikacja globalnej bez `global`** → `UnboundLocalError`. Najczęstsza pułapka scope'u.
- **`global` to złe podejście** w prawdziwym kodzie — lepiej **zwracać z funkcji**. Wzmiankuj, ale powiedz: w 90% kodu nie używaj `global`.
- **Cyrkularne importy** (A importuje B, B importuje A) — pułapka większych projektów. Wzmianka.
- **`from math import *`** (gwiazdką) — anty-idiom. Importuje wszystko, brudzi przestrzeń nazw, nie wiadomo skąd co.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **`dataclasses`** — krótka wzmianka jako "wygodny pomost między funkcjami a klasami" (moduł 7):
```python
from dataclasses import dataclass

@dataclass
class Punkt:
    x: float
    y: float

p = Punkt(3, 4)
print(p)  # Punkt(x=3, y=4) — gotowy __repr__
```
Powiedz: pełna dyskusja w module 7 (OOP), tu tylko wzmianka.
- **Type hints**:
```python
def srednia(liczby: list[float]) -> float:
    return sum(liczby) / len(liczby)
```
Standard 2026 dla nowych funkcji. Wzmianka, nie wymuszanie.

## Notatki tutora
- **Scope bywa abstrakcyjny** — używaj metafory "pokoju z notatnikiem" ile się da.
- **`global` to ostatnia deska ratunku** — pokaż, ale natychmiast pokazuj alternatywę "zwróć z funkcji".
- **Własny moduł to PRZEŁOM** dla ucznia — pierwsze przeczucie "to skaluje się do prawdziwych projektów".
- **Nie wchodź w pakiety** (`__init__.py`, podkatalogi) — moduł 11 (projekt).
