# Lekcja 12.3 — Gdzie szukać dalej + AI-assisted coding

## Cel
Po lekcji uczeń:
- Wie gdzie szukać odpowiedzi (docs, StackOverflow, Discord, AI)
- Używa AI (Claude Code / Copilot) **świadomie** jako uzupełnienia, nie zamiennika nauki
- Ma listę 5-10 konkretnych zasobów do dalszej nauki
- Wie jak zacząć kontrybucję do open source

## Krok 1 — Zakotwiczenie (3 min)
**Pytanie wejściowe:**
> "Skończyłeś podstawy języka. Co byś zrobił, jeśli **utkniesz** na czymś, czego nie wiesz?"

**Co chcesz usłyszeć:** dokumentacja, Google, znajomi, AI. To **umiejętność szukania** — często ważniejsza niż znajomość konkretnej składni.

## Krok 2 — Mostek (5 min)
**Mostek:** "Programowanie to **ciągła nauka**. Wiedza dezaktualizuje się, biblioteki się zmieniają. Kluczowa umiejętność: **wiedzieć gdzie i jak szukać**. AI to nowy gracz w tym świecie — potężny, ale wymagający rozsądku."

## Krok 3 — Eksperyment — zasoby i strategie (15-20 min)

### Hierarchia szukania pomocy

**Pierwszy ruch — przeczytaj komunikat błędu:**
- Python 3.12+ podpowiada "Did you mean: 'len'?"
- Traceback wskazuje **linię** i **typ błędu**
- Zatrzymaj się, przeczytaj, **myśl** — często odpowiedź jest tam

**Drugi ruch — dokumentacja:**
- https://docs.python.org/3/ — **najlepsza** dokumentacja, OFICJALNA
- Każda biblioteka ma swoją: `requests.readthedocs.io`, `pandas.pydata.org`, etc.
- W VS Code: hover na funkcji → dokumentacja **w okienku**

**Trzeci ruch — Google + StackOverflow:**
- Wpisz konkretny błąd: `"ModuleNotFoundError: No module named 'requests'"`
- StackOverflow zazwyczaj pierwsza odpowiedź. **Czytaj zaakceptowaną**, ale sprawdź też komentarze.
- **Sortuj po dacie** — odpowiedzi z 2015 mogą być przestarzałe.

**Czwarty ruch — AI (Claude, GPT, Copilot):**
- Wklej kontekst (kod + błąd) i opisz cel
- AI da odpowiedź — **przeczytaj ze zrozumieniem**, nie kopiuj na ślepo
- Jeśli AI sugeruje bibliotekę, **sprawdź czy istnieje** (czasem halucynuje)
- Pytaj "dlaczego" — uczy więcej niż "co"

**Piąty ruch — społeczność:**
- Discord PyCoders Poland (polskie)
- r/learnpython na Reddit
- Github Discussions konkretnego projektu

### AI-assisted coding — używaj świadomie

**Co AI robi DOBRZE:**
- Generuje boilerplate (importy, stub funkcji)
- Sugeruje refactor (rename, split funkcji)
- Tłumaczy obcy kod
- Generuje testy z funkcji (lub funkcję z testów)
- Wyjaśnia error message

**Co AI robi ŹLE / WYMAGA UWAGI:**
- Halucynuje biblioteki / funkcje, które nie istnieją
- Sugeruje przestarzałe podejścia (z 2020 zamiast 2026)
- Może nie znać specyfiki najnowszego Pythona
- Pisze "zgodny" ale niepoprawny kod
- Nie wie o Twoim konkretnym kontekście biznesowym

**Reguła ZŁOTA:** "AI to **wzmacniacz**, nie zamiennik. Jeśli kopiujesz kod, którego nie rozumiesz — tracisz naukę, a kod ma **bugi**, których nie wykryjesz."

**Świadome użycie:**
```
"Napisz funkcję, która..."          ← AI generuje
"Wyjaśnij linijka po linijce..."    ← czytasz
"Dlaczego tutaj X?"                 ← pytasz
"Jak to przetestować?"              ← AI sugeruje testy
TY URUCHAMIASZ I SPRAWDZASZ
```

## Krok 4 — Pogłębienie — open source i kariera (10 min)

### Pierwsza kontrybucja open source

1. **Znajdź mały projekt** używany przez Ciebie (biblioteka z `pip list`)
2. **Issues z tagiem "good first issue"** — projekty często mają takie
3. **Spróbuj naprawić** (literówka w docs, mały bug)
4. **Pull Request** — opisz co i czemu
5. **Pierwszy zaakceptowany PR** — wpis do CV

## Pułapki
- **Tutoriale forever** — uczysz się, ale nie buduszysz. Wybierz **projekt**.
- **Skakanie między językami** ("a może JavaScript?") — najpierw Python solidnie.
- **AI bez zrozumienia** — produktywnie krótko, długoterminowo regres.
- **Izolacja** — bez społeczności programowanie jest trudniejsze.
- **Perfekcjonizm** — "jeszcze nie jestem gotowy" — JESTEŚ. Skończyłeś kurs.
